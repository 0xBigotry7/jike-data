# 集刻经营情报台：持续采集与发布

## 客户价值与发布规则

首页优先呈现能触发采购核价、同商圈实采或鲜食试点的少量证据。每条包含来源、来源日期、采集日期、地区、交易条件/使用边界与下一步动作。历史事件的补充发现不能称“今天发生”；搜索摘要不等于重新获取了当前报价。不得将研究记录数称为独立 SKU 数，或把首次基线称为新动态。

只使用无需登录的公开网页、搜索摘要、政府监测和正式披露。不登录、不绕过访问限制、不联系供应商或客户。不采用户私有 POS、凭证或客户内部经营信息到公开仓库。疑似引流/蹭牌报价排除。价格 CSV 必须严格 9 列：品类,SKU,规格,批发价低,批发价高,零售价,促销低价,来源,日期；数字不含单位，单位必须在规格/报告明确。未知留空，估计注明估计，不产生假精度。

## 两层机制

1. GitHub Actions 每 6 小时计划检查 `sources.json` 中的固定来源，采用网站允许的访问方式。调度可能延迟；公开仓库长期无活动时 GitHub 可停用计划。运行后提交 `dist/watch.json` 并部署 Pages。失败留痕，保留上次成功快照；首次抓取和提取规则变更均作为基线，不触发正文变化。来源数量以实际配置和每轮结果为准，不声称覆盖全行业。
2. 当前 Codex 任务每日 09:30（Asia/Shanghai）计划执行跨来源 AI 研究。依赖本机与 Codex 调度可用，并非云端常驻 AI 服务。每轮最多两个窄任务，使用 gpt-5.6-luna；每个 SKU/主题最多打开详情 1 次，每个任务详情不超过 15 次，优先使用搜索摘要，失败换来源不重试。先读已有报告与 JSON 去重，不重复堆数据。

## 每轮流程

- 检查网站 git 状态和 remote main；保留用户未提交改动。读取 `dist/watch.json`、`signals.json`、`incremental.json`、最新报告及 `../research/round6`。对来源失败和正文差异先判断是否值得调查。
- 轮换两类窄任务：① 成都可配送的同条码、同箱规报价与保质期/起订/税运；② 成都竞对新品、活动期限、夜间服务和供应链公告；后续扩到食材周价、季节需求与鲜食生产条件。优先近 7–30 天有明确日期的第一方资料；旧资料补齐必须标注历史。
- 同 SKU/规格/来源/交易期比对，保留 new/revisit/correction/unchanged；多来源不是多个 SKU，原报价没变不能写成降价。来源日期、采集日期、商品生产日期和报价有效期分开。
- 原始候选保存在研究目录；报告编号从当前最大编号递增，末尾有“数据缺口”表。经复核、适合公开的记录才增量加入 `dist/incremental.json` 和报告库。一次最多 3 条首页重点：写清事实、对集刻的可能影响、可执行步骤及证据边界。不足 3 条就少展示，不强凑。
- `signals.json` 是已复核编辑线索，`watch.json` 是机器正文变化；不能混成已确认商业事件。累计采集审计写入 `monitor/runs/`，记录实际查了什么、新增/重访/排除数量、失败原因和下一轮缺口。
- 运行采集器单测、JSON/CSV 校验、前端语法检查；涉及布局时验证 390px 和桌面，以及筛选/详情/下载。无新结论只留运行记录，不重写首页。
- 发布用户已授权的公开项目文件到 GitHub 仓库 `0xBigotry7/jike-data` main，经 Pages 部署至 `https://jike-data.sailinglabs.cn/`。优先使用已连接 GitHub 工具，若无 git 推送凭证可使用 create_tree / create_commit / update_ref。必须以最新远端为 parent，禁止强推、禁止覆盖其他未审改动，禁止提交凭证、私有 KB 或原始未审候选。确认部署成功后再说已上线。
- 仅在有有用的新证据、需要处理的持续失败或需要用户行动时通知；状态无变化保持安静。

## 文件口径

- `dist/decision.js` / `.css`：客户行动页面；`workbench.js` 保留完整证据搜索。
- `dist/incremental.json`：第六轮起的已复核增量观察，使用现有记录字段与 `origin: round6`；重复关系及观察时间保留。
- `dist/signals.json`：编辑精选，包含 `checked_at`、`items`、每项 `source_date` / `collected_at` / `source_url` / `region` / `evidence` / `action` / `boundary`。
- `dist/watch.json`：实际采集健康状态、历史与正文差异。不能用手工时间伪造采集运行。
- `dist/reports-incremental.json` 和 `dist/reports/NN.md`：完整报告配套更新。现有 `build_library.py` 依赖项目研究目录，云端不可直接重建；基础 `reports.json` 保留 01–115，之后报告在 `reports-incremental.json` 按编号追加。

当前阶段的承诺是持续发现并辅助核实；有效到店价、实销量、报损与即时库存需要供应商或门店回填后才能用于正式经营决策。
